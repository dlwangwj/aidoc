方案架构、服务详解、典型场景与迁移映射。产品名与功能来自训练知识，未联网核实，选型前请以腾讯云官网最新文档为准。

一、方案定位

腾讯云的思路是轻量化：以 DLC（数据湖计算）为统一查询入口，COS 做湖存储，WeData 做开发治理。组件少、上手快，适合以 SQL 为主、希望快速上线的分析团队。

适合

SQL 为主的分析团队快速上线运维资源有限

不太适合

复杂 Spark 作业深度流计算与 ML

核心难点

治理能力需额外评估复杂作业兼容性

四、典型方案

方案 A：SQL 数仓快速上线

  1. 数据通过 WeData 集成到 COS，存为 Iceberg 表。
  2. DLC 统一查询，分析师直接写 SQL。
  3. WeData 调度与质量校验，BI 报表接入 DLC。

方案 B：实时指标看板

  1. 消息数据进入 Oceanus（Flink）做聚合。
  2. 结果写入 TCHouse，用于高并发查询。
  3. BI 工具刷新看板。

方案 C：Spark 作业与 ML 结合

  1. EMR 或 DLC 上运行 Spark 特征工程。
  2. 特征写入 COS 的 Iceberg 表。
  3. TI-ONE 训练并推理，结果回写数仓。

五、从 Databricks 迁移的映射

Databricks 概念腾讯云对应迁移注意点
Delta 表Iceberg 表需要转换表格式。Delta 的部分高级特性需要确认在 DLC 上的支持情况。
Unity CatalogDLC 元数据 + 权限治理能力较轻，跨工作空间的统一治理需要额外设计。
Databricks JobsWeData 调度需要重建任务依赖，参数传递方式需要适配。
SQL WarehouseDLC / TCHouseSQL 方言需逐一核对，尤其是窗口函数与日期函数。
NotebookWeData Notebook代码基本可复用，依赖库与环境需要重新配置。
MLflowTI-ONE 实验管理实验记录格式不同，需要单独迁移。

六、优劣势

优势

  • 入口统一，DLC 同时支持 SQL 与 Spark，学习成本低。
  • 运维负担轻，Serverless 为主，适合小团队。
  • 上手快，适合快速建设分析能力。

劣势

  • 复杂 Spark 作业与深度流计算的能力弱于阿里云与火山引擎。
  • 治理能力需要额外评估，尤其是血缘与跨团队权限。
  • ML 集成相对较弱，需要自行打通。

七、选型检查清单

  1. 现有 Spark 作业用了哪些 API？需要确认 DLC 的兼容性。
  2. 数据量与并发查询量是否适合 DLC 的计费模式？
  3. 是否需要 TCHouse 做低延迟查询？
  4. 治理与血缘要求是否能被 WeData 满足？
  5. ML 需求是否需要 TI-ONE 的完整能力？
