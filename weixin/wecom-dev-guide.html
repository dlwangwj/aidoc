企业微信开发对比指南

智能机器人开发  vs  企业自建应用开发 —— 功能、接入方式与选型一览

说明：本页基于企业微信公开文档的通用知识整理，未在线核对官方最新版本。接口名、参数、权限范围以 官方开发者文档 为准。

一、两者一句话概括

1智能机器人

一个可被员工在单聊、群聊中 @ 或直接对话的 AI/对话式机器人。 核心能力是收消息 → 处理 → 流式回复，偏向"对话交互"场景。

典型场景：智能问答、知识库助手、工单查询、审批提醒、运维助手。

2企业自建应用

企业在管理后台创建的独立应用，拥有 AgentId 与 Secret， 通过 access_token 调用企业微信全套服务端 API，偏向"系统集成"场景。

典型场景：OA/ERP/CRM 集成、消息推送通知、通讯录同步、网页应用（H5）单点登录。

四、接入方式与调用流程

智能机器人 消息链路

员工在单聊/群聊发消息
→
企微推送事件
长连接 / 回调
→
开发者服务解析
→
流式回复
stream 分段
  • 长连接模式：开发者服务主动与企微建立 WebSocket，适合内网部署、无公网 IP 的场景。
  • 回调模式：企微把消息 POST 到开发者配置的 URL，需校验签名并解密。

企业自建应用 调用链路

用 CorpID + Secret
→
获取 access_token
有效期约 7200s，需缓存
→
调用业务 API
message/send、通讯录等
  • 接收消息：在应用中配置"接收消息服务器"URL、Token、EncodingAESKey，企微以 XML 加密回调。
  • 网页应用：配置可信域名 → 用户在企微内打开网页 → OAuth2 获取 userid → 前端/后端完成登录。

五、代码示例（Python）

自建应用 获取 token 并发送消息

import time, requests

CORP_ID = "ww_xxx"
AGENT_ID = 1000002
SECRET = "xxx"

_token_cache = {"token": None, "expire": 0}

def get_access_token():
    # access_token 有效期约 7200 秒，应缓存复用，不要每次请求都获取
    if _token_cache["token"] and time.time() < _token_cache["expire"]:
        return _token_cache["token"]
    url = "https://qyapi.weixin.qq.com/cgi-bin/gettoken"
    data = requests.get(url, params={"corpid": CORP_ID, "corpsecret": SECRET}).json()
    _token_cache["token"] = data["access_token"]
    _token_cache["expire"] = time.time() + data["expires_in"] - 300  # 提前 5 分钟刷新
    return _token_cache["token"]

def send_text(userid, content):
    url = "https://qyapi.weixin.qq.com/cgi-bin/message/send"
    body = {
        "touser": userid,
        "msgtype": "text",
        "agentid": AGENT_ID,
        "text": {"content": content},
    }
    return requests.post(url, params={"access_token": get_access_token()}, json=body).json()

send_text("zhangsan", "部署已完成 ✅")
智能机器人的收发消息是事件驱动的：消息通过长连接或回调到达，回复时需在同一会话上下文中返回， 流式回复需按"开始 → 多次刷新 → 结束"的顺序发送。具体报文格式请以官方文档为准。

六、如何选择

✅ 选 智能机器人，如果：
  • 核心需求是"员工和 Bot 对话"
  • 需要在群里 @ 机器人、流式输出 AI 回答
  • 不需要网页、不需要通讯录管理
  • 服务部署在内网，希望免公网（长连接）
✅ 选 企业自建应用，如果：
  • 需要主动向员工推送业务通知
  • 需要读写通讯录、部门、标签
  • 需要做 H5 网页、OAuth 单点登录、JS-SDK
  • 与 OA、ERP、监控等系统做深度集成
常见组合：用自建应用做系统通知和网页入口，用智能机器人做对话式交互，两者可在同一项目中共存。

七、开发注意事项

  • access_token 必须缓存：频繁获取会触发频率限制，且会使旧 token 失效。
  • 可见范围：自建应用只能推送给可见范围内的成员，否则返回权限错误。
  • 可信 IP：服务端调用 API 的出口 IP 需加入应用的可信 IP 列表。
  • 可信域名：网页应用的域名必须备案并在后台配置，否则 OAuth 与 JS-SDK 不可用。
  • 加解密：回调请求需校验签名并解密，注意 Token 与 EncodingAESKey 不要泄露。
  • 权限与接口版本：通讯录等接口需在应用权限中勾选，接口能力可能随版本变化，上线前请核对官方文档。
